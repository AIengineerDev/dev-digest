# PR Brief — Development Plan

**Spec:** `specs/10-pr-brief.md`
**Execution mode:** parallel tracks (2 tracks, after a single-threaded contract + schema prelude)

## Goal / Done when

A reviewer opening a PR's Overview tab sees a card that states what the PR changes, why, its risk level, its grounded risks and an ordered "read these first" list — generated by exactly one ≤8 000-token model call, cached per PR state so a second view costs nothing, with every file and endpoint it names verified in code against the PR's own inputs.

## Corrections after cross-model review

`plans/10-pr-brief.cross-model-review.md` (gpt-5, 2026-08-18) found four things
this plan got wrong. They override the phase text below wherever they conflict.

**C-1 — Smart Diff roles are computed, not stored. Blocking.** Phase A1's select
and Phase A2's `files` parameter both assume a `role` column on `pr_files`.
There is none (`server/src/db/schema/pulls.ts:36-42`); role is derived per
request from path patterns (`server/src/modules/smart-diff/helpers.ts:43`,
`smart-diff/constants.ts`). `no-cross-module-internals` forbids importing it.
**Fix:** move the classifier and its pattern table to
`server/src/modules/_shared/file-roles.ts` and have `smart-diff` re-export from
there, exactly the move `plans/09-project-context.plan.md` Phase T3 makes for
the walk limits. `brief` imports `_shared`, which is a permitted target. This
lands in **Phase P1**, not A1 — it is a shared-module move and both tracks'
type-checking depends on it.

**C-2 — No `''` sentinels in the primary key.** P1's composite PK cannot hold
NULLs, and the plan's answer was to store `''` for a missing
`intent_fingerprint` / `repo_indexed_sha`. That collides with a legitimately
empty value and produces cache behaviour nobody can debug. **Fix:** keep both
columns nullable, drop them from the primary key, and enforce C10 with a
**partial unique index** over the seven components using
`COALESCE(intent_fingerprint, '')` — the uniqueness is still in Postgres, which
was the point, without a sentinel that can be confused for data.

**C-3 — The injection-guard test must assert effect, not presence.** A2's A15
checks that `<untrusted>` wrappers are present. A wrapper whose guard text is
missing or wrong is decorative, and the test would still pass. **Fix:** the test
feeds a hostile string that instructs the model to ignore its instructions and
asserts (a) it appears only inside a wrapper, (b) it is escaped where it mimics
a delimiter, and (c) the system prompt contains the guard clause that gives the
wrapper meaning. Assert the guard's text, not just that some guard exists.

**C-4 — `maxRetries` must be `0`.** R3 says one call, no repair call; an
adapter-level retry is a second billed request, making the worst case
2 x 8 000 input tokens. A budget stated in the acceptance criteria cannot be
quietly doubled. **Fix:** `maxRetries: 0`. A malformed structured response is a
degradation (`error: 'ungrounded_output'` path), not a retry. Recorded as
amendment A-1 on the spec.

**Not corrected, deliberately:** the reviewer's finding that R6's "unless
degraded" exception changes the contract is real, and is fixed on the **spec**
side as amendment A-2 (the Retry button sends `force=true`), not here.

## Contract changes

All in `server/src/vendor/shared/contracts/brief.ts`, then mirrored by `./scripts/check-shared.sh --fix`. Client copy is never hand-edited.

```
ReviewFocusItem = { kind: 'file' | 'endpoint', ref: string, reason: string, line?: number }
Brief           = { what, why, risk_level: RiskSeverity, risks: Risk[], review_focus: ReviewFocusItem[] }
BriefRecord     = Brief.extend({
                    pr_id, head_sha, intent_fingerprint, repo_indexed_sha,
                    provider, model, prompt_version,
                    tokens_in, tokens_out, cost_usd, budget_tokens,
                    dropped_inputs: string[], dropped_refs: number,
                    degraded: boolean, error: string | null, generated_at: string | null
                  })
```

- `RiskSeverity` (`contracts/brief.ts:101`) and `Risk` (`:104-111`) are **reused**, not redefined. `Risk.kind` stays `z.string()` (Q5).

## Traps for this change

- **`server/clones/**` holds a full copy of this repository.** Exclude it from every grep and glob or you will read and edit the wrong `brief.ts`.
- **`pr_files.patch` is one column from everything the brief wants.** `container.reviewRepo.getPrFiles` returns `$inferSelect` **including** `patch` (`server/src/modules/reviews/repository.ts:38-40`), and `GET /pulls/:id` returns it on `PrDetail.files[].patch` (`modules/pulls/helpers.ts:137-142`). Reading either as a convenience violates R2 silently. Three walls: a three-column select, an assembly signature with no patch-shaped member, and A4's sentinel test.
- **`no-cross-module-internals` counts `import type`.** `tsPreCompilationDeps: true` (`.dependency-cruiser.cjs:113`) means `import type { BlastService } from '../blast/service.js'` is a violation. Every cross-module value reaches the brief through `container.*`.
- **Do not add a container getter onto another module's `service.ts`.** Services take `Container` for DI, so the getter creates a new import cycle unprotected by the 5 baselined ones (`server/INSIGHTS.md`, 2026-08-09). Nothing here needs one.
- **The arch baseline is 10, not 11**, and it is `--ignore-known`. Never run `arch:all` and never regenerate `.dependency-cruiser-known-violations.json` to clear a failure.
- **`check-shared.sh --fix` rsyncs server → client with `--delete`.** Edit the server copy. A client-only edit is destroyed. And `client/src/lib/feature-models.ts` is **not** covered by it — Q7 needs both.
- **Migrations are generated, never written.** Edit `schema/reviews.ts`, then `pnpm db:generate`. Add-only is one clean pass; the two-generate rule applies only when one table both gains and loses columns.
- **Postgres rejects NULL in a primary-key column.** `intent_fingerprint` and `repo_indexed_sha` are legitimately absent (null intent, never-indexed repo). Store `''`. Leaving them nullable produces silent duplicate rows for exactly the two cases the spec treats as routine.
- **No transactions exist anywhere in the server.** Do not assume a repository method is atomic. Generation is one upsert, so nothing here needs a boundary — but C1 exists *because* `GET /pulls/:id` deletes then re-inserts `pr_files` without one.
- **The seeded demo repo can never exercise `repo-intel`.** Every local run produces a degraded blast input. A green suite says nothing about the indexed path.
- **The client has zero error boundaries** across 86 `.tsx`. A render throw blanks the page with no toast. C12's fallback icon is load-bearing.
- **`src/vendor/**` is vendored** — `client/src/vendor/ui` and both `vendor/shared` trees. `client/src/components/diff-viewer/` is **not** vendored and is editable. `NAV` lives in vendored `src/vendor/ui/nav.ts`; this feature **adds no route**, so no sidebar entry is needed and nothing ships unreachable.
- **Not a monorepo.** `server/` and `client/` are **pnpm**; `e2e/`, `reviewer-core/` and `mcp/` are **npm**. `cd e2e && npm run e2e:hermetic`.
- **Verify the branch alone on top of `main`.** Route registration, hook barrel export, message keys and the arch rule are the four lines that merge cleanly from someone else's commit and leave the feature inert (root `INSIGHTS.md`, 2026-08-16). Phase J1's checklist exists only for this.
- **CI is path-filtered.** Five workflows, each scoped to its own paths. A change outside a filter is checked by nothing. The gates in this plan are the gates that matter.

## Risks and unknowns

- **`BriefRecord` is frozen at P0 and the tracks build against it.** If Track A discovers `dropped_inputs: string[]` needs structure (e.g. `{ input, reason }`), both tracks stop, the contract changes server-side once, `--fix` re-mirrors, and both resume. Mitigation: P0 lands the field list at full fidelity from the spec (`:258`) rather than incrementally.
- **`container.tokenizer.count` is `cl100k_base` — OpenAI's encoding — and Q7 points `risk_brief` at an Anthropic model.** The drift between `budget_tokens` and the provider's `usage.input_tokens` will be systematic, not noise. The spec concedes it could not be measured without real calls. If the drift runs high, the effective ceiling is below 8 000 and C14 fires more often than expected; if low, the reverse. R10 records both numbers so this is answerable after ~20 real briefs. **Nothing in the plan changes** — but the 8 000 constant lives in `modules/brief/constants.ts` so it is one edit.
- **The per-input budgets are an allocation, not an observation, and they sum to 8 500** (audit row 2). Real PRs may blow past the ceiling routinely, making C14's refusal the common path rather than the exception. If so, the fix is the drop order and the per-row caps, both of which are pure functions in `assemble.ts` with tests — cheap to retune. If it turns out most PRs need more than 8 000, that is a spec change, not a plan change.
- **The counts row being client-derived is my assumption, not the spec's statement** (audit row 5). If the CTO wants it persisted, add three columns to `BriefRecord` and the table, compute them server-side, and accept that a cached brief shows counts frozen at generation. That change touches P0, P1, A3 and B2 — cheapest to decide **before** P0.
- **`router.push` vs `router.replace` for the focus jump** (audit row 7). If R9's mechanism is meant to bind and C11's Back behaviour is the thing to give up, B3 changes by one call.
- **Unknown, ~20 minutes to check:** whether `next-intl`'s `NextIntlClientProvider` accepts an `onError` that can rethrow in the vitest/jsdom setup this repo uses, which is what makes A16 literally checkable. If it cannot, A16 degrades to asserting no literal appears in the rendered output — weaker but still a real gate. Check before writing B1's test, not after.
- **Unknown, ~15 minutes to check:** whether `FileCard`'s root element is a stable place to hang an `id` given how `DiffViewer` maps over files, or whether the anchor belongs on a wrapper. Affects only B3's first commit.
- **The seeded demo cannot produce a non-degraded blast radius**, so R4's reference set locally contains no endpoints and every endpoint the model names is dropped (C8). This is correct behaviour, and it means the automated suite exercises the *degraded* grounding path only. The real-repo check in J1 is the only coverage of the other one — do not skip it because the suite is green.
